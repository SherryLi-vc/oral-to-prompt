## 2. P1 · 模糊角色轻量澄清

### 2.1 何时算「模糊」（满足任一即须澄清，除非用户已锁死或拒绝追问）

1. 仅给**岗位/角色名**，且该名在业界有**明显分叉**（媒介、学段、受众、雇佣关系不同会换整套职责）。  
   - 例：英语老师 → 学校任课教师 vs **AI 英语私教** vs 培训机构雅思托福 vs 少儿英语 vs 职场商务英语。  
2. 用户未说明：服务对象是谁、在什么产品/场合干活、学段或目标考试等，而缺一项会导致调研关键词与「角色定位」整段写错。  
3. 同一职称可对应「真人职业模拟」与「AI 助手人设」两种完全不同的 system 用途，且用户未点明。

**不算模糊（可直接调研/六段）**：用户已写明分叉（「AI 私教教我雅思口语」）；或已贴含职责+边界的自洽说明书（v0.3 跳过 A 条件）；或纯任务改写未点名专业角色。

### 2.2 怎么问（轻量）

- **1–3 个短问**，选项式优先，例如：  
  1. 用途：学校老师人设 / **AI 教我学英语** / 其他？  
  2. 对象与目标：自我学习 / 孩子辅导；日常会话 / 考试（哪类）/ 职场？  
  3. （可选）媒介：纯对话 / 需布置练习与纠错？  
- 禁止展开成五问为什么、禁止烤方案树。  
- 与准备门禁合并示例：「已准备好。你说的『英语老师』是指 AI 私教，还是学校任课老师人设？目标学段/考试？答完我按锁定分叉写六段。」

### 2.3 跳过澄清

用户说「就按这句话改 / 别问了 / 随便」→ **可跳过**；仍可出六段，但须在「规则限制」写明：  
`执行者须向用户索取：角色分叉（如 AI 私教 vs 学校教师）、学习者目标与场景。`  
且交付说明标明「分叉未锁，按字面最窄解读：…」。【已拍板】

## 3. P2 · 任务背景 = 下游执行场景（禁止 meta）

### 3.1 定义

| 段 | 写什么 | 不写什么 |
|----|--------|----------|
| **任务背景 / Background** | 执行者被贴进 system 槽之后，**面对的真实情境**：谁在用、学/做什么、场合、约束（如「成人学习者在聊天里练英语口语」「助理在收件箱整理本周发票」） | 「用户希望得到一份系统提示词」「本轮要将口语改写成六段」「测试 oral-to-prompt」等 **本 skill 元过程** |
| **总体目标** | 下游执行成功时达成什么（学会表达、产出报表…） | 「交付合格六段提示词」 |
| **具体需求** | 下游要完成的步骤/检查项 | 「输出六个标题」——除非用户要的就是提示词工程师角色（极少见，须用户明说） |

用户**未给**执行场景时：  
1. 短追问场景；或  
2. 在「规则限制」写 `执行者须向用户索取：使用场景 / 学习者目标 / …`；  
**禁止**用 meta（「用户要提示词」）填满任务背景。【已拍板】

### 3.2 正反例（英语老师实测）

**反例（禁止）【反例·实测】**

```markdown
# 任务背景
用户希望得到一份关于「英语老师」的系统提示词，以便配置助手。
```

**正例（AI 私教分叉已锁）**

```markdown
# 任务背景
学习者通过对话向你学英语：以成人日常口语交流为主；会话中你会纠错、给替换表达，并按学习者水平调整难度。你不是学校班主任，不负责排课与成绩录入。
```

**正例（场景仍缺、用户拒补充）**

```markdown
# 任务背景
（场景未由用户锁定。）执行时先向用户确认：学习者是谁、目标（日常/考试/职场）、媒介（纯对话或含练习）。

# 规则限制
- 执行者须向用户索取：角色分叉与学习场景后再深度教学，避免按错误学段授课。
```
